## สไลด์ที่ทำเสร็จแล้ว

### `slides/01-title.html` — หน้าจอเปิดเกม GBC

2 beat: (1) กรอบ title เลื่อนลง → รอคลิก (2) คนเดินเข้าซ้าย + หุ่นลอยเข้าขวา
→ ทักทาย → หันเข้าหากันคุยกันเองไปเรื่อยๆ → รอคลิก → exit วูบมืด ไปสไลด์ 2
`▶ LET'S BEGIN` ทำหน้าที่เป็น "ไฟรอ input" โผล่ทุกครั้งที่จบ beat

### `slides/02-levels.html` — บันได 4 ระดับ

4 beat = 4 ระดับ เสาโผล่ทีละต้น + คนกระโดดขึ้นไปยืน เสาเก่าค้างไว้
เหนือบันไดมีแถบแสดงของกลางจอ เปลี่ยนตาม beat (แชท → prompt มีโครงสร้าง →
เอกสาร 2 ชั้น → เอกสาร 5 ชั้น + เครื่องมือ 6 ชิ้น) **ไม่มีหุ่นในสไลด์นี้โดยตั้งใจ**
ไอคอนเครื่องมือปั้นเป็น SVG พิกเซล 13×13 อยู่ในตัวแปร `ICONS` ในไฟล์สไลด์

### `slides/03-chat.html` — ระดับ 01 Chat เล่าด้วยบทสนทนาจริง

หน้าต่างแชทกลางจอ **1 คลิก = 1 ข้อความ** รวม 17 ข้อความ ฝั่งเราขวา (ครีมเหลือง)
ฝั่ง AI ซ้าย ทุกฟองมี avatar พิกเซลหน้าคน/หน้าหุ่นกำกับ กล่องสูงคงที่
ข้อความเก่าเลื่อนขึ้นหายไปเรื่อยๆ ไม่มี scrollbar
เคส IT support ออเดอร์ ORD123 กดยืนยันไม่ผ่าน — AI เดาผิด 4 รอบ
(สต็อก / ราคา-โปรโมชัน / กรอกไม่ครบ / สิทธิ์ซื้อ) แล้วขอ context เอง
พอได้ log ก็เจอว่าที่อยู่รายนี้อยู่นอกพื้นที่จัดส่งที่ระบบรู้จัก แล้วจบงานได้
ปิดท้ายด้วย `🙂👌`

**ใต้กล่องแชทมีฉากวนลูป** ไม่ผูกกับ beat เริ่มทันทีที่เข้าสไลด์ — หุ่นทำงานอยู่
ใน **ตู้ rack** ฝั่งซ้าย คนยืนรอฝั่งขวา คนเรียก → หุ่นออกมาคุย → หุ่นกลับเข้าตู้
ทำ **3 รอบ** รอบสุดท้ายคนขึ้น `✅` แล้ววนใหม่ (ตัวละคร 30% ของสไลด์ 1)

### `slides/04-prompt.html` — ระดับ 02 Prompt ยุบ 17 ข้อความเป็นข้อความเดียว

**6 beat** สองกล่องเทียบกัน: ซ้าย = บทสนทนาสไลด์ 3 ย่อเหลือแถวละบรรทัด 17 แถว /
ขวา = หน้าต่างแชทใหม่ที่ยังว่าง

1. เปิดมาเห็นทั้ง 17 แถว
2. **ซิป** — 8 แถวฝั่ง AI จางแล้วยุบสูงเป็น 0 กองรูดปิด หัวกล่อง 17 → 9
3. **FLIP** — 7 แถวที่เป็นข้อมูลจริงบินไปประกอบเป็น**ฟองแชทใบเดียว** พร้อมรูปหน้าจอ
   กับ log ที่แนบมาด้วย / 2 แถวที่ไม่ใช่ข้อมูล (ขอบคุณ + `🙂👌`) จางหายไปเฉยๆ
4. หน้าต่างแชทเลื่อนมากลางเวที + AI ขึ้นจุดสามจุด (= ส่งแล้ว)
5. คำตอบมาในฟองถัดไป root cause ตรงเป้าตั้งแต่คำตอบแรก
6. สรุป **17 → 2** + บรรทัดยอมรับว่ารอบแรกยังไม่รู้ว่าต้องแนบ log

ตัวนับหัวกล่องขวาไล่ 0 → 1 → 2 ข้อความ ขนานกับ 17 ของกล่องซ้าย

**ฉากล่างวนลูปเหมือนสไลด์ 3 แต่รอบเดียวจบ** (~22.5s) และ**บอลลูนฝั่งคน
"ค่อยๆ พิมพ์"** เป็น skeleton ย่อส่วนของฟองพรอมต์ (ย่อหน้า → บุลเล็ต 3 →
กล่องรูป → ย่อหน้าปิด) แต่ละแท่งกางจาก 0 บอลลูนขยายตาม หุ่นยืนรอตลอด
ฝั่งหุ่นยังโผล่ทั้งก้อนแบบเดิม — ตัดกันว่าคนใช้เวลาเรียบเรียง หุ่นตอบพรวดเดียว

### `slides/05-context.html` — ระดับ 03 Context ยกของที่ซ้ำไปไว้ในไฟล์เดียว

**6 beat** ซ้าย = ไฟล์ `context/order-error.md` / ขวา = หน้าต่างแชท

1. พรอมต์ยาวใบเดิมจากสไลด์ 4 ผ่าสองกอง — `เฉพาะเคสนี้` / `เหมือนกันทุกเคส`
2. กองที่ซ้ำยุบหายจากฟอง แล้วกลายเป็น**ไฟล์ใบเดียว** ฝั่งซ้าย โผล่ทีละบล็อก
   (หัวเรื่อง+ย่อหน้า → ที่อยู่ของของ 5 บรรทัด → ขั้นตอน 4 ข้อ → ฟอร์แมตคำตอบ)
3. ตั๋วใหม่ พิมพ์**ประโยคเดียว** ชิปชื่อไฟล์โผล่ใต้ข้อความ "แนบไปด้วยเสมอ"
4. ได้ root cause ตั้งแต่คำตอบแรก + **ไฮไลต์บรรทัดในไฟล์ที่หยิบไปใช้**
5. ตั๋วใบที่สอง อาการ "ค้าง ไม่มี error" ไฟล์เดิมไม่ได้แก้ **แต่ไฮไลต์ย้ายไปคนละบรรทัด**
6. หน้าต่างแชทจางหาย ตั๋วใบ 3-4-5 ซ้อนขึ้นมาแทน + `···` + บรรทัดกันโกง

**ฉากล่างมีตู้เก็บของ `.store` เพิ่มมาข้างตู้ rack** พอหุ่นเข้าไปทำงาน ช่องในตู้จะไล่ไฟ
= หุ่นไปเปิดไฟล์อ่านเอง คนไม่ต้องยื่นให้ **ลูปสั้นกว่าสไลด์ 4 เกือบครึ่ง (~19.5s)**
เพราะคนพูดคำเดียวจบ ไม่ต้องค่อยๆ พิมพ์เหมือนสไลด์ 4 — ความสั้นนี่แหละคือใจความ
ทั้งฉากเลื่อนไปกิน x 302..978 (เดิม 342..938) เพราะมีตู้เก็บของเพิ่มมา

### ระบบที่ใช้ร่วมกันทุกสไลด์

- เวที 1280×720 ตายตัว scale ให้พอดีจอ
- ระบบ **beat** — คลิก/`Space`/`→` เดินหน้าทีละจังหวะ / `←` ถอย / `R` reset
- ปุ่มมุมล่างขวา **ไม่มีกรอบ** เป็นกลิฟจาง `opacity .28` ชัดตอน hover:
  `◀ ▶ pips ↺ AUTO` — สไลด์ 3 (17 beat) กับสไลด์ 4 (6 beat) ใช้เลข `n/N` แทน pips
- เส้นพื้น `bottom: 28px` (สไลด์ 1–2) / `30px` (ฉากสไลด์ 3) / `18px` (ฉากสไลด์ 4
  ที่เตี้ยกว่า 16px)
- รองรับโหมด iframe ด้วย `postMessage({type:"slide:next"|"slide:prev"})`

## เรื่องที่เคยคุยแล้วตกลงแล้ว (อย่ารื้อ)

- ของประกอบแต่ละ beat **แทนที่ ไม่สะสม**
- ข้อความในกล่อง/บอลลูนของ**ฉากตัวละคร** อ่านไม่ออกโดยตั้งใจ (แท่งขีด/สัญลักษณ์)
  เพื่อไม่ให้คนดูมัวอ่านแทนที่จะฟัง — ส่วนเนื้อสไลด์หลัก (สไลด์ 3–4) อ่านออกจริง
- beat ละ micro loop เดียว (beat 4 ของสไลด์ 2 มีสอง)
- **ไอคอน / องค์ประกอบ UI** ใช้ SVG ปั้นเอง **ห้าม emoji** (บังคับสีไม่ได้
  แตกพาเลตต์) และไม่ใช้ Unicode glyph (หน้าตาเปลี่ยนตามฟอนต์เครื่องที่ฉาย)
- **ข้อยกเว้น (ตกลงกัน 2026-08-29): emoji ใช้ได้เฉพาะเป็นสีหน้า/อารมณ์ของตัวละคร**
  เช่น `🙂👌` `✅` ในสไลด์ 3–4 — user รับความเสี่ยงเรื่องสีกับฟอนต์แล้ว
  แต่ **ไอคอน UI ยังห้ามใช้ emoji เหมือนเดิม**
- กติกา `--accent` แดงจุดเดียวต่อสไลด์ — **ผ่อนปรนแล้ว** ใช้ตามหน้างานได้
  สไลด์ 1 ใช้ที่หมวกหุ่น / สไลด์ 2 ใช้ที่เลขระดับของเสาที่ยืนอยู่ /
  สไลด์ 4 ใช้ที่เลข `2` ในบรรทัดสรุป

- **error code `00412`** ตัวเลข 5 หลักล้วน ไม่มี prefix ตัวอักษร — เดิมร่างเป็น
  `ORD-4021` แต่ไปชนรูปแบบรหัส ticket จริงของทีมอื่นในบริษัท เลยเปลี่ยน

  เวอร์ชันแรกทำเป็นการ์ดมีป้ายช่อง 4 ช่อง + เส้นประรอเติม user ตีกลับเพราะ
  **มันเป็นภาษาภาพของ "เทมเพลต/โครงสร้าง" ซึ่งเป็นของสไลด์ 5 (context engineer)**
  ระดับ 02 ต้องเป็นแค่ "คุณพิมพ์ข้อความเดียวให้ครบ" ป้ายกำกับเลยกลายเป็นคำนำหน้า
  บรรทัดในตัวข้อความเอง (`เช็คไปแล้วดังนี้ครับ`)
  → **อย่าเอาเส้นประ / ช่องกรอก / ป้ายหัวช่องกลับมา**
- **แอนิเมชันยุบเลือกแบบ "ซิป → FLIP" เป็นสองบีต** (หนึ่งบีตหนึ่งความคิด)
  แบบที่พิจารณาแล้วไม่เอา: กองแล้วอัดเป็นการ์ดใบเดียว (ระหว่างอัดอ่านอะไรไม่ได้เลย) /
  ตัวหนังสือไหลออกจากฟอง (ต้อง clone ทุก text node แพงและเปราะ)
- **บีต 6 ต้องยอมรับว่ารอบแรกยังไม่รู้ว่าต้องแนบ log** ไม่งั้นคนดูจับได้ว่าโกง
  เพราะ log เป็นสิ่งเดียวใน 17 ข้อความที่ AI เป็นคนขอ ไม่ใช่ของที่มีอยู่ในหัวแต่แรก
- **ฟองปลายทางต้องถูกวางเต็มใบตั้งแต่ต้น beat 3 (เนื้อในล่องหน)** ห้ามเปลี่ยนไปเป็น
  "ค่อยๆ ต่อชิ้นเข้าไป" ไม่งั้นชิ้นหลังๆ วัดตำแหน่งแล้วบินไปลงผิดที่

## สไลด์ 5 — เรื่องที่ตกลงแล้ว (อย่ารื้อ)

- **ไฟล์เดียวเท่านั้น** (user ตีกลับเวอร์ชันแรก 2026-08-30) เวอร์ชันแรกทำเป็น
  **ชั้นวางที่มีการ์ดหลายใบ + ซ็อกเก็ตต่อ DB/log + แผงชื่อเครื่องมือ
  (Claude Code / Codex / Cursor)** ตีกลับทั้งชุด ระดับ 03 ต้องเป็นแค่
  *"คุณเขียนไฟล์ไว้ใบเดียว แล้วมันถูกแนบไปทุกครั้ง"* เรื่อง DB / log / API
  ยังอยู่แต่อยู่**ในไฟล์ ในฐานะ "ที่อยู่ของของ"** ไม่ใช่ท่อที่ต่อจริง
  → **อย่าเอาชั้นวางหลายชิ้น / ซ็อกเก็ต / ชื่อเครื่องมือ กลับมา**
- **ประโยคที่พิมพ์ในบีต 3 ต้องเป็นข้อความแรกของสไลด์ 3 คำต่อคำ**
  `ออเดอร์ ORD123 ลูกค้ากดยืนยันไม่ผ่านครับ ระบบขึ้น ERROR 00412` — ประโยคเดียวกันเป๊ะที่สไลด์ 3
  ได้คำเดาผิดกลับมา 4 รอบ มาคราวนี้ถูกตั้งแต่คำตอบแรก **มุกทั้งสไลด์อยู่ตรงนี้**
  ถ้าจะแก้ต้องแก้ `03-chat.html` พร้อมกัน
- **มุกรอง: ไฟล์เดียวกันเป๊ะ แต่สองใบใช้คนละบรรทัด** ใบ 1 ไฮไลต์ `DB` + `โค้ดที่ตรวจ`
  + ขั้นตอน 2,3 / ใบ 2 ไฮไลต์ `Log` + `API` + ขั้นตอน 1,2 — นี่คือสิ่งที่ทำให้
  "ไฟล์เดียวพอ" จับต้องได้ ไม่ใช่แค่คำพูด
- **ตั๋วใบที่สองต้องเป็นอาการที่ไม่มีรหัส error** (กด checkout แล้วค้าง) ไม่งั้นมันจะไป
  ใช้บรรทัดชุดเดิมกับใบแรก แล้วมุก "คนละบรรทัด" ไม่เกิด
- **บรรทัดกันโกงบีต 6 ห้ามตัด** — *ไฟล์ไม่ได้เขียนตัวเอง ต้องมีคนเขียนและคอยอัปเดต
  และมันบอกได้แค่ว่าของอยู่ที่ไหน ใครจะไปหยิบมาให้ ยังเป็นอีกเรื่อง*
  ประโยคหลังคือสะพานไปสไลด์ agent harness
- **ที่อยู่ในไฟล์เป็นโดเมนสมมติทั้งหมด** (`shop.example.com` / `pg-prod`)
  อย่าเอาของจริงของบริษัทใส่
- **`setBeat()` ต้องเรียก `rebuild(n-1)` ก่อนรัน `STEP[n]` เสมอ** เจอบั๊กจริงตอนกดรัว
  200ms แล้วไฟล์หายทั้งอัน เพราะ timer ของบีตก่อนโดน `clearTimers()` ล้างก่อน
  ได้ทำงาน — อย่าถอดออก
