## สไลด์ที่ทำเสร็จแล้ว

### `slides/01-title.html` — หน้าจอเปิดเกม GBC

2 beat: (1) กรอบ title เลื่อนลง → รอคลิก (2) คนเดินเข้าซ้าย + หุ่นลอยเข้าขวา
→ ทักทาย → หันเข้าหากันคุยกันเองไปเรื่อยๆ → รอคลิก → exit วูบมืด ไปสไลด์ 2
`▶ LET'S BEGIN` ทำหน้าที่เป็น "ไฟรอ input" โผล่ทุกครั้งที่จบ beat

### `slides/02-levels.html` — บันได 4 ระดับ

4 beat = 4 ระดับ เสาโผล่ทีละต้น + คนกระโดดขึ้นไปยืน เสาเก่าค้างไว้
เหนือบันไดมีแถบแสดงของกลางจอ เปลี่ยนตาม beat (แชท → prompt มีโครงสร้าง →
เอกสาร 2 ชั้น → เอกสาร 5 ชั้น + เครื่องมือ 6 ชิ้น) **ไม่มีหุ่นในสไลด์นี้โดยตั้งใจ**
ไอคอนเครื่องมือปั้นเป็น SVG พิกเซล 13×13 อยู่ในตัวแปร `ICONS` ในไฟล์สไลด์

### ระบบที่ใช้ร่วมกันทั้งสองสไลด์

- เวที 1280×720 ตายตัว scale ให้พอดีจอ
- ระบบ **beat** — คลิก/`Space`/`→` เดินหน้าทีละจังหวะ / `←` ถอย / `R` reset
- ปุ่มมุมล่างขวา **ไม่มีกรอบ** เป็นกลิฟจาง `opacity .28` ชัดตอน hover:
  `◀ ▶ pips ↺ AUTO`
- เส้นพื้น `bottom: 28px` เท่ากันทั้งสองสไลด์
- รองรับโหมด iframe ด้วย `postMessage({type:"slide:next"|"slide:prev"})`

## เรื่องที่เคยคุยแล้วตกลงแล้ว (อย่ารื้อ)

- ของประกอบแต่ละ beat **แทนที่ ไม่สะสม**
- ข้อความในกล่อง/บอลลูน **อ่านไม่ออกโดยตั้งใจ** (แท่งขีด/สัญลักษณ์)
  เพื่อไม่ให้คนดูมัวอ่านแทนที่จะฟัง
- beat ละ micro loop เดียว (beat 4 ของสไลด์ 2 มีสอง)
- ไอคอนใช้ SVG ปั้นเอง **ไม่ใช้ emoji** (บังคับสีไม่ได้ แตกพาเลตต์)
  และไม่ใช้ Unicode glyph (หน้าตาเปลี่ยนตามฟอนต์เครื่องที่ฉาย)
- กติกา `--accent` แดงจุดเดียวต่อสไลด์ — **ผ่อนปรนแล้ว** ใช้ตามหน้างานได้
  สไลด์ 1 ใช้ที่หมวกหุ่น / สไลด์ 2 ใช้ที่เลขระดับของเสาที่ยืนอยู่

## สไลด์ 3 — คุยออกแบบไว้แล้ว ยังไม่ได้เขียนโค้ด (2026-08-29)

**เปลี่ยนแผนจาก outline เดิม:** สไลด์ 3 จะ**พูดเรื่อง chat เลย** ไม่ใช่ "ยกตัวอย่างงาน"
ตาม outline (= ช่วง 3 ถูกยุบ/ควบรวมเข้ากับช่วง 4) — user ยืนยันทิศทางนี้แล้ว
ไฟล์เป้าหมายยังใช้ชื่อ `slides/03-examples.html` ตามที่ `NEXT` ของสไลด์ 2 ชี้ไว้
(ถ้าจะเปลี่ยนชื่อไฟล์ ต้องแก้ `NEXT` ในสไลด์ 2 ด้วย)

**เลือก use case แล้ว: เคส IT support — ลูกค้าสร้าง order ไม่ได้**
เป็นเส้นเรื่องเดียวที่จะลากยาวไปถึงสไลด์ agent harness (ticket ใบเดิม คนเดิม
แต่ยกระดับวิธีใช้ AI ทีละสไลด์) ตามที่ NOTES ล็อกไว้

**หน้าตา:** กลางจอเป็นกล่องข้อความแชท คุยกันไปเรื่อยๆ **เป็นบทสนทนาไทยจริงที่อ่านออก**
(ต่างจากสไลด์ 1–2 ที่ข้อความอ่านไม่ออกโดยตั้งใจ — สไลด์นี้เนื้อหาคือตัวสาระ)

**บทที่ user ชอบ: แบบ B→C ต่อกัน** = AI เดาผิดหลายรอบ แล้วจบด้วยการขอ context เอง
ลำดับที่ร่างไว้ (user ขอให้เพิ่มประเด็นมากกว่าเรื่อง cache อย่างเดียว + ขอให้มีการส่งรูป):

1. คุณ: ลูกค้าสร้าง order ไม่ได้ log ขึ้น `ORD-4021` → AI: เดาว่าสินค้าหมดสต็อก
2. คุณ: สินค้ามีสต็อก 200 ชิ้น → AI: เดาว่าเป็น cache
3. คุณ: ล้างแล้วยังเหมือนเดิม **+ ส่งรูปหน้าจอ error** → AI: อ่านรูปผิวๆ ตอบว่าปุ่มเป็นสีเทา น่าจะกรอกไม่ครบ
4. คุณ: กรอกครบแล้ว กดได้ กดแล้วถึงเด้ง error → AI: เดาว่าเป็นเรื่องสิทธิ์ user
5. คุณ: **คนอื่นสร้างได้ คนนี้คนเดียวที่ไม่ได้** → AI: ขอ log เต็ม + โค้ดส่วนที่ตรวจ order 🎯

> บรรทัด 5 คือหัวใจ — บีบให้เห็นว่าคำตอบอยู่ที่*ข้อมูลของลูกค้าคนนั้น* ซึ่ง chat ล้วนไม่มีทางรู้
> แล้วส่งไม้ต่อให้สไลด์ context engineer พอดี

**บีตเสริมที่เสนอไว้ ยังไม่ได้เลือก** — (ก) AI วนกลับมาเสนอวิธีเดิม
(ข) AI อ่านรูปเกินเลยไปเรื่องเวลา/ระบบปิดปรับปรุง (ค) AI โยนให้ "ติดต่อทีมพัฒนา"
แล้วเราตอบว่า "เราคือทีมนั้น" — ตลกสุดแต่เสี่ยงกลบประเด็น

**ข้อเสนอเชิงเทคนิคที่ยังไม่ได้เคาะ:**

- รูปในแชทวาดเป็น**กล่องพิกเซล** (กรอบหนา + แถบหัว + `⚠` + แท่งขีด ~120×80)
  แบบเดียวกับเอกสาร/เครื่องมือในสไลด์ 2 ไม่ใช่รูปจริง
- แบ่ง beat แบบ **1 beat = 1 คู่สนทนา (คุณถาม + AI ตอบ)** → ได้ 5 beat พอๆ กับสไลด์อื่น
- กล่องแชท**เลื่อนขึ้นเองเหมือนแชทจริง** ข้อความเก่าไหลขึ้น อันใหม่โผล่ล่าง แก้ปัญหาพื้นที่
