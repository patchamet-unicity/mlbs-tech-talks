## สไลด์ที่ทำเสร็จแล้ว

### `slides/01-title.html` — หน้าจอเปิดเกม GBC

2 beat: (1) กรอบ title เลื่อนลง → รอคลิก (2) คนเดินเข้าซ้าย + หุ่นลอยเข้าขวา
→ ทักทาย → หันเข้าหากันคุยกันเองไปเรื่อยๆ → รอคลิก → exit วูบมืด ไปสไลด์ 2
`▶ LET'S BEGIN` ทำหน้าที่เป็น "ไฟรอ input" โผล่ทุกครั้งที่จบ beat

### `slides/02-levels.html` — บันได 4 ระดับ

4 beat = 4 ระดับ เสาโผล่ทีละต้น + คนกระโดดขึ้นไปยืน เสาเก่าค้างไว้
เหนือบันไดมีแถบแสดงของกลางจอ เปลี่ยนตาม beat (แชท → prompt มีโครงสร้าง →
เอกสาร 2 ชั้น → เอกสาร 5 ชั้น + เครื่องมือ 6 ชิ้น) **ไม่มีหุ่นในสไลด์นี้โดยตั้งใจ**
ไอคอนเครื่องมือปั้นเป็น SVG พิกเซล 13×13 อยู่ในตัวแปร `ICONS` ในไฟล์สไลด์

### `slides/03-chat.html` — ระดับ 01 Chat เล่าด้วยบทสนทนาจริง

หน้าต่างแชทกลางจอ **1 คลิก = 1 ข้อความ** รวม 17 ข้อความ ฝั่งเราขวา (ครีมเหลือง)
ฝั่ง AI ซ้าย ทุกฟองมี avatar พิกเซลหน้าคน/หน้าหุ่นกำกับ กล่องสูงคงที่
ข้อความเก่าเลื่อนขึ้นหายไปเรื่อยๆ ไม่มี scrollbar
เคส IT support ลูกค้าสร้าง order ไม่ได้ — AI เดาผิด 4 รอบ (สต็อก / cache / รูป / สิทธิ์)
แล้วขอ context เอง พอได้ log ก็เจอ root cause `creditLimit = null` แล้วจบงานได้
ปิดท้ายด้วย `🙂👌`

**ใต้กล่องแชทมีฉากวนลูป** ไม่ผูกกับ beat เริ่มทันทีที่เข้าสไลด์ — หุ่นทำงานอยู่
ใน **ตู้ rack** ฝั่งซ้าย คนยืนรอฝั่งขวา คนเรียก → หุ่นออกมาคุย → หุ่นกลับเข้าตู้
ทำ 3 รอบ รอบสุดท้ายคนขึ้น `✅` แล้ววนใหม่ (ตัวละคร 30% ของสไลด์ 1)
ตู้อยู่ `z-index` สูงกว่าตัวละคร หุ่นเลยเลื่อนหายเข้าไปหลังตู้จริงๆ
ตอนหุ่นอยู่ข้างใน ตู้ติดคลาส `is-busy` → LED กะพริบถี่ + แถบสแกนเขียวไล่ลงมา
**ทั้งฉากต้องอยู่กลางจอเสมอ** (ขอบซ้ายตู้ 342 ถึงขอบขวาคน 938 กึ่งกลาง 640)
ขยับค่าไหนต้องเลื่อนทั้งชุด — เคยพลาดมาแล้วสองรอบ

### ระบบที่ใช้ร่วมกันทั้งสามสไลด์

- เวที 1280×720 ตายตัว scale ให้พอดีจอ
- ระบบ **beat** — คลิก/`Space`/`→` เดินหน้าทีละจังหวะ / `←` ถอย / `R` reset
- ปุ่มมุมล่างขวา **ไม่มีกรอบ** เป็นกลิฟจาง `opacity .28` ชัดตอน hover:
  `◀ ▶ pips ↺ AUTO` — สไลด์ 3 มี 17 beat เลยเปลี่ยน pips เป็นเลข `n/17`
- เส้นพื้น `bottom: 28px` (สไลด์ 1–2) / `30px` (ฉากล่างของสไลด์ 3)
- รองรับโหมด iframe ด้วย `postMessage({type:"slide:next"|"slide:prev"})`

## เรื่องที่เคยคุยแล้วตกลงแล้ว (อย่ารื้อ)

- ของประกอบแต่ละ beat **แทนที่ ไม่สะสม**
- ข้อความในกล่อง/บอลลูน **อ่านไม่ออกโดยตั้งใจ** (แท่งขีด/สัญลักษณ์)
  เพื่อไม่ให้คนดูมัวอ่านแทนที่จะฟัง
- beat ละ micro loop เดียว (beat 4 ของสไลด์ 2 มีสอง)
- **ไอคอน / องค์ประกอบ UI** ใช้ SVG ปั้นเอง **ห้าม emoji** (บังคับสีไม่ได้
  แตกพาเลตต์) และไม่ใช้ Unicode glyph (หน้าตาเปลี่ยนตามฟอนต์เครื่องที่ฉาย)
- **ข้อยกเว้น (ตกลงกัน 2026-08-29): emoji ใช้ได้เฉพาะเป็นสีหน้า/อารมณ์ของตัวละคร**
  เช่น `🙂👌` `✅` ในสไลด์ 3 — user รับความเสี่ยงเรื่องสีกับฟอนต์แล้ว
  แต่ **ไอคอน UI ยังห้ามใช้ emoji เหมือนเดิม**
- กติกา `--accent` แดงจุดเดียวต่อสไลด์ — **ผ่อนปรนแล้ว** ใช้ตามหน้างานได้
  สไลด์ 1 ใช้ที่หมวกหุ่น / สไลด์ 2 ใช้ที่เลขระดับของเสาที่ยืนอยู่

## สไลด์ 3 — เรื่องที่ตกลงแล้ว (อย่ารื้อ)

- **เปลี่ยนแผนจาก outline เดิม** สไลด์ 3 พูดเรื่อง chat เลย ไม่ใช่ "ยกตัวอย่างงาน"
  (= ช่วง 3 ถูกยุบรวมเข้ากับช่วง 4) ชื่อไฟล์เลยเป็น `03-chat.html` ไม่ใช่ `03-examples.html`
- **use case ล็อกแล้ว: IT support — ลูกค้าสร้าง order ไม่ได้** เส้นเรื่องเดียวนี้
  จะลากยาวไปถึงสไลด์ agent harness (ticket ใบเดิม คนเดิม แต่ยกระดับวิธีใช้ AI)
- **ข้อความอ่านออกจริง** ต่างจากสไลด์ 1–2 ที่เป็นแท่งขีด เพราะที่นี่เนื้อบทคือสาระ
- **บทจบด้วยความสำเร็จ ไม่ใช่ทางตัน** — chat ไม่ได้ผิด แค่แพงเวลา
- **root cause = `creditLimit` เป็น null** เลือกเพราะเป็นข้อมูลเฉพาะลูกค้ารายนั้น
  ที่ AI ไม่มีทางเดาถูก → ส่งไม้ต่อสไลด์ context engineer พอดี
- **error code `00412`** ตัวเลข 5 หลักล้วน ไม่มี prefix ตัวอักษร — เดิมร่างเป็น
  `ORD-4021` แต่ไปชนรูปแบบรหัส ticket จริงของทีมอื่นในบริษัท เลยเปลี่ยน
- **บีตเสริมที่เคยเสนอ ไม่ได้เอา** (AI วนเสนอวิธีเดิม / อ่านรูปเกินเลย /
  โยนให้ "ติดต่อทีมพัฒนา") — ถ้าจะเพิ่มทีหลัง เพิ่มใน `MSGS` ได้เลย
- **บรรทัดสรุปใต้กล่องแชทถูกตัดออกแล้ว** (เคยเป็น `16 ข้อความ · 4 รอบแรกคือการเดา`)
  จำนวนรอบยังเป็นประเด็นที่จะเอาไปเทียบในสไลด์ prompt/context แต่ผู้พูดพูดเอง
  ไม่ขึ้นบนจอ
