## สไลด์ที่ทำเสร็จแล้ว

### `slides/01-title.html` — หน้าจอเปิดเกม GBC

2 beat: (1) กรอบ title เลื่อนลง → รอคลิก (2) คนเดินเข้าซ้าย + หุ่นลอยเข้าขวา
→ ทักทาย → หันเข้าหากันคุยกันเองไปเรื่อยๆ → รอคลิก → exit วูบมืด ไปสไลด์ 2
`▶ LET'S BEGIN` ทำหน้าที่เป็น "ไฟรอ input" โผล่ทุกครั้งที่จบ beat

### `slides/02-levels.html` — บันได 4 ระดับ

4 beat = 4 ระดับ เสาโผล่ทีละต้น + คนกระโดดขึ้นไปยืน เสาเก่าค้างไว้
เหนือบันไดมีแถบแสดงของกลางจอ เปลี่ยนตาม beat (แชท → prompt มีโครงสร้าง →
เอกสาร 2 ชั้น → เอกสาร 5 ชั้น + เครื่องมือ 6 ชิ้น) **ไม่มีหุ่นในสไลด์นี้โดยตั้งใจ**
ไอคอนเครื่องมือปั้นเป็น SVG พิกเซล 13×13 อยู่ในตัวแปร `ICONS` ในไฟล์สไลด์

### `slides/03-chat.html` — ระดับ 01 Chat เล่าด้วยบทสนทนาจริง

หน้าต่างแชทกลางจอ **1 คลิก = 1 ข้อความ** รวม 9 ข้อความ ฝั่งเราขวา (ครีมเหลือง)
ฝั่ง AI ซ้าย ทุกฟองมี avatar พิกเซลหน้าคน/หน้าหุ่นกำกับ กล่องสูงคงที่
ข้อความเก่าเลื่อนขึ้นหายไปเรื่อยๆ ไม่มี scrollbar
เคส IT support user EMP042 ล็อกอินเข้า StaffHub ไม่ได้ — AI เดา account ถูก lock
ก่อน แล้วสงสัยเรื่องสิทธิ์ พอเห็นรูป Access denied ก็ขอ login log เอง
พอได้ log ก็เจอว่าฝั่งสิทธิ์ยังอ้างอิงแผนก Sales อยู่ ทั้งที่ user ย้ายไป Finance
ตั้งแต่เมื่อวาน แล้วจบงานได้ ปิดท้ายด้วย `🙂👌`

**ใต้กล่องแชทมีฉากวนลูป** ไม่ผูกกับ beat เริ่มทันทีที่เข้าสไลด์ — หุ่นทำงานอยู่
ใน **ตู้ rack** ฝั่งซ้าย คนยืนรอฝั่งขวา คนเรียก → หุ่นออกมาคุย → หุ่นกลับเข้าตู้
ทำ **3 รอบ** รอบสุดท้ายคนขึ้น `✅` แล้ววนใหม่ (ตัวละคร 30% ของสไลด์ 1)

### `slides/04-prompt.html` — ระดับ 02 Prompt ยุบ 9 ข้อความเป็นข้อความเดียว

**6 beat** สองกล่องเทียบกัน: ซ้าย = บทสนทนาสไลด์ 3 ย่อเหลือแถวละบรรทัด 9 แถว /
ขวา = หน้าต่างแชทใหม่ที่ยังว่าง

1. เปิดมาเห็นทั้ง 9 แถว
2. **ซิป** — 4 แถวฝั่ง AI จางแล้วยุบสูงเป็น 0 กองรูดปิด หัวกล่อง 9 → 5
3. **FLIP** — 4 แถวที่เป็นข้อมูลจริงบินไปประกอบเป็น**ฟองแชทใบเดียว** พร้อมรูปหน้าจอ
   กับ log ที่แนบมาด้วย / 1 แถวที่ไม่ใช่ข้อมูล (sync แล้วเข้าได้) จางหายไปเฉยๆ
4. หน้าต่างแชทเลื่อนมากลางเวที + AI ขึ้นจุดสามจุด (= ส่งแล้ว)
5. คำตอบมาในฟองถัดไป root cause ตรงเป้าตั้งแต่คำตอบแรก
6. สรุป **9 → 2** + บรรทัดที่ชี้ว่าเรื่องย้ายแผนกคุณรู้ตั้งแต่แรก

ตัวนับหัวกล่องขวาไล่ 0 → 1 → 2 ข้อความ ขนานกับ 9 ของกล่องซ้าย

**ฉากล่างวนลูปเหมือนสไลด์ 3 แต่รอบเดียวจบ** (~22.5s) และ**บอลลูนฝั่งคน
"ค่อยๆ พิมพ์"** เป็น skeleton ย่อส่วนของฟองพรอมต์ (ย่อหน้า → บุลเล็ต 3 →
กล่องรูป → ย่อหน้าปิด) แต่ละแท่งกางจาก 0 บอลลูนขยายตาม หุ่นยืนรอตลอด
ฝั่งหุ่นยังโผล่ทั้งก้อนแบบเดิม — ตัดกันว่าคนใช้เวลาเรียบเรียง หุ่นตอบพรวดเดียว

### `slides/05-context.html` — ระดับ 03 Context ยกของที่ซ้ำไปไว้ในไฟล์เดียว

**6 beat** ซ้าย = ไฟล์ `context/staffhub-access.md` / ขวา = หน้าต่างแชท

1. พรอมต์ยาวใบเดิมจากสไลด์ 4 ผ่าสองกอง — `เฉพาะเคสนี้` / `เหมือนกันทุกเคส`
2. **พับ → บิน → คลี่** ไฟล์เปล่าโผล่มาก่อน แล้วย่อหน้าในกอง `keep` พับเป็นแถบบางๆ
   บินข้ามไปฝั่งซ้ายทีละอัน แล้วคลี่ออกเป็นบล็อกในไฟล์ (3 ย่อหน้า → 4 บล็อก ตาราง `FOLD`)
   **การจับคู่คือส่วนที่ให้ข้อมูล** ทำให้เห็นว่าไฟล์คือของเดิมที่ย้ายที่ ไม่ใช่ของใหม่
   ท่านี้จงใจไม่ให้ซ้ำสไลด์ 4 (นั่นคือของบินมาประกอบกัน อันนี้คือของถูกพับเก็บเข้าแฟ้ม)
3. ตั๋วใหม่ พิมพ์**ประโยคเดียว** ชิปชื่อไฟล์โผล่ใต้ข้อความ "แนบไปด้วยเสมอ"
4. ได้ root cause ตั้งแต่คำตอบแรก + **ไฮไลต์บรรทัดในไฟล์ที่หยิบไปใช้**
5. ตั๋วใบที่สอง ทีม Marketing เข้าแล้วค้าง ไฟล์เดิมไม่ได้แก้ **แต่ไฮไลต์ย้ายไปคนละบรรทัด**
6. หน้าต่างแชทจางหาย ตั๋วใบ 3-4-5 ซ้อนขึ้นมาแทน + `···` + บรรทัดกันโกง

**ฉากล่างมีตู้เก็บของ `.store` เพิ่มมาข้างตู้ rack** พอหุ่นเข้าไปทำงาน ช่องในตู้จะไล่ไฟ
= หุ่นไปเปิดไฟล์อ่านเอง คนไม่ต้องยื่นให้ **ลูปสั้นกว่าสไลด์ 4 เกือบครึ่ง (~19.5s)**
เพราะคนพูดคำเดียวจบ ไม่ต้องค่อยๆ พิมพ์เหมือนสไลด์ 4 — ความสั้นนี่แหละคือใจความ
ทั้งฉากเลื่อนไปกิน x 302..978 (เดิม 342..938) เพราะมีตู้เก็บของเพิ่มมา

## เรื่องที่เคยคุยแล้วตกลงแล้ว (อย่ารื้อ)

- ของประกอบแต่ละ beat **แทนที่ ไม่สะสม**
- ข้อความในกล่อง/บอลลูนของ**ฉากตัวละคร** อ่านไม่ออกโดยตั้งใจ (แท่งขีด/สัญลักษณ์)
  เพื่อไม่ให้คนดูมัวอ่านแทนที่จะฟัง — ส่วนเนื้อสไลด์หลัก (สไลด์ 3–4) อ่านออกจริง
- beat ละ micro loop เดียว (beat 4 ของสไลด์ 2 มีสอง)
- **ไอคอน / องค์ประกอบ UI** ใช้ SVG ปั้นเอง **ห้าม emoji** (บังคับสีไม่ได้
  แตกพาเลตต์) และไม่ใช้ Unicode glyph (หน้าตาเปลี่ยนตามฟอนต์เครื่องที่ฉาย)
- **ข้อยกเว้น (ตกลงกัน 2026-08-29): emoji ใช้ได้เฉพาะเป็นสีหน้า/อารมณ์ของตัวละคร**
  เช่น `🙂👌` `✅` ในสไลด์ 3–4 — user รับความเสี่ยงเรื่องสีกับฟอนต์แล้ว
  แต่ **ไอคอน UI ยังห้ามใช้ emoji เหมือนเดิม**
- กติกา `--accent` แดงจุดเดียวต่อสไลด์ — **ผ่อนปรนแล้ว** ใช้ตามหน้างานได้
  สไลด์ 1 ใช้ที่หมวกหุ่น / สไลด์ 2 ใช้ที่เลขระดับของเสาที่ยืนอยู่ /
  สไลด์ 4 ใช้ที่เลข `2` ในบรรทัดสรุป

  บรรทัดในตัวข้อความเอง (`เช็คไปแล้วดังนี้ครับ`)
  → **อย่าเอาเส้นประ / ช่องกรอก / ป้ายหัวช่องกลับมา**
- **แอนิเมชันยุบเลือกแบบ "ซิป → FLIP" เป็นสองบีต** (หนึ่งบีตหนึ่งความคิด)
  แบบที่พิจารณาแล้วไม่เอา: กองแล้วอัดเป็นการ์ดใบเดียว (ระหว่างอัดอ่านอะไรไม่ได้เลย) /
  ตัวหนังสือไหลออกจากฟอง (ต้อง clone ทุก text node แพงและเปราะ)
- **บีต 6 ต้องชี้ว่าเรื่องย้ายแผนกคุณรู้ตั้งแต่แรก แต่เพิ่งบอกตอนข้อความที่ 7**
  นั่นคือสารทั้งหมดของสไลด์นี้ — ไม่ใช่ว่า AI เก่งขึ้น แต่คุณส่งของให้ครบตั้งแต่ทีเดียว
- **ฟองปลายทางต้องถูกวางเต็มใบตั้งแต่ต้น beat 3 (เนื้อในล่องหน)** ห้ามเปลี่ยนไปเป็น
  "ค่อยๆ ต่อชิ้นเข้าไป" ไม่งั้นชิ้นหลังๆ วัดตำแหน่งแล้วบินไปลงผิดที่

  ยังอยู่แต่อยู่**ในไฟล์ ในฐานะ "ที่อยู่ของของ"** ไม่ใช่ท่อที่ต่อจริง
  → **อย่าเอาชั้นวางหลายชิ้น / ซ็อกเก็ต / ชื่อเครื่องมือ กลับมา**
