ขั้นตอนที่ให้ไล่

  1. อ่าน login log ของ user ในช่วงเวลาที่แจ้ง
  2. เทียบข้อมูล user ใน DB กับสิทธิ์ที่ระบบใช้จริง
  3. เช็คว่าเพิ่งย้ายแผนกหรือเปลี่ยนตำแหน่งหรือไม่
  4. ถ้าข้อมูลไม่พอ ให้ขอเพิ่ม อย่าเดา

context/logs.md

Logs

รายละเอียดตัวอย่างสำหรับไล่เหตุการณ์ sign-in ของ StaffHub

tool: search_logs   [illustrative]
serverlogs-prod-01.internal / 10.42.18.24
sourceLoki datasource: staffhub-prod · service: auth-api
ค้นด้วยemployee ID และช่วงเวลาที่ผู้ใช้แจ้ง
หลักฐานtimestamp, status/error, correlation ID
$ search_logs --employee EMP042 --since "09:15" --until "09:30"
2026-09-04T09:22:18Z 403 department_mismatch corr=8f21
procedureยืนยัน time window แล้วเก็บ correlation ID ไปเทียบ request ถัดไป
context/database.md

Database

รายละเอียดตัวอย่างสำหรับเทียบข้อมูลพนักงานกับสิทธิ์ที่ระบบใช้

tool: query_db   [illustrative / read-only]
replicastaffhub-ro-01.internal / 10.42.22.17:5432 / staffhub
schemastaffhub.users, employee_permissions, roles
joinemployee → user → role
เทียบค่าactive, department, assigned_role, synced_at
SELECT u.department, p.assigned_role, p.synced_at
FROM users u JOIN employee_permissions p USING (employee_id)
WHERE u.employee_id = 'EMP042';
ตัวอย่างเท่านั้น: ใช้ read-only connection และไม่ใส่ secrets
context/permissions.md

Permissions และ business rules

กฎตัวอย่างที่ใช้แปลข้อมูลจาก log และ database

rolesStaff, Manager, HR Admin, IT Support
scopeเห็นข้อมูลเฉพาะแผนกที่ได้รับมอบหมาย
terminatedต้องถอนสิทธิ์เข้า StaffHub
transferย้ายแผนกแล้วต้อง refresh สิทธิ์
ownerIdentity ดู rule; HR ยืนยันข้อมูลพนักงาน
$ jobctl status permission-sync-hourly
last_run=2026-09-04T09:00Z  status=ok  batch=illustrative
escalationส่ง correlation ID และ employee ID ให้ owner ที่เกี่ยวข้อง
context/response-format.md

Response format

template สำหรับสรุปโดยไม่ปนสิ่งที่เห็นกับสิ่งที่คาด

Findingสิ่งที่พบจากข้อมูลที่ตรวจแล้ว
Evidencetimestamp และแหล่งที่มาของหลักฐาน
Immediate actionวิธีแก้เฉพาะหน้าที่ตรวจผลได้
Long-term actionสิ่งที่ลดการเกิดซ้ำ
Owner / next checkใครรับต่อ และเช็คผลที่จุดใด
## Finding
Observed: role ยังอ้างอิง Sales
Inference: sync หลังย้ายแผนกไม่ครบ
Action: refresh permission แล้วให้ user ลองใหม่
ไม่เปิด secrets และติดป้าย observed evidence แยกจาก inference
