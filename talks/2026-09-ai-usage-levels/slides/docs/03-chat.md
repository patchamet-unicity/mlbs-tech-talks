## beat

**1 beat = 1 ข้อความ** (ไม่ใช่ 1 คู่สนทนา) → `BEATS = MSGS.length` = **16**

| beat | ใคร | ใจความ |
| --- | --- | --- |
| 1–2 | คุณ / AI | แจ้ง error `00412` → AI เดา "สินค้าหมดสต็อก" |
| 3–4 | คุณ / AI | มีสต็อก 200 → AI เดา "cache" |
| 5–6 | คุณ / AI | ล้างแล้วไม่หาย **+ แนบรูปหน้าจอ** → AI อ่านรูปผิวๆ "ปุ่มเป็นสีเทา" |
| 7–8 | คุณ / AI | ปุ่มกดได้ กดแล้วถึงเด้ง → AI เดา "สิทธิ์ user" |
| 9–10 | คุณ / AI | **คนอื่นสร้างได้ คนนี้คนเดียวที่ไม่ได้** → AI ขอ log + โค้ด 🎯 |
| 11–12 | คุณ / AI | **แนบ log + โค้ด** → AI เจอ root cause `creditLimit = null` |
| 13–14 | คุณ / AI | ถามวิธีแก้ → AI เสนอเฉพาะหน้า + ระยะยาว |
| 15–16 | คุณ / AI | แก้แล้วใช้ได้ → AI เตือนว่าลูกค้ารายอื่นที่ยังไม่ตั้งวงเงินก็จะเจอ |

จบ beat 16 แล้ว **หน่วง 950ms** บรรทัดสรุป `16 ข้อความ · 4 รอบแรกคือการเดา`
ค่อยโผล่ใต้กล่อง — กดอีกทีถึงไปสไลด์ถัดไป

### ทำไมบทเป็นแบบนี้

- **root cause ต้องเป็นข้อมูลเฉพาะลูกค้ารายนั้น** (`creditLimit` เป็น null)
  เพราะเป็นสิ่งเดียวที่อธิบาย "คนอื่นได้ คนนี้ไม่ได้" ได้ และเป็นสิ่งที่
  AI **ไม่มีทางเดาถูก** ถ้าเราไม่ให้ → ส่งไม้ต่อสไลด์ context engineer พอดี
- **จบด้วยความสำเร็จจริง ไม่ใช่ทางตัน** — ประเด็นของ talk คือ
  "chat ไม่ได้ผิด แค่แพงเวลา" ไม่ใช่ "chat ใช้ไม่ได้"
- **ตัวเลข 16 / 4** ในบรรทัดสรุปจะถูกเอาไปเทียบในสไลด์ prompt / context
  ว่ายกระดับแล้วเหลือกี่รอบ → ถ้าแก้บท **ต้องแก้ตัวเลขในบรรทัดสรุปด้วย**
- error code เป็น **`00412`** ตัวเลข 5 หลักล้วน — จงใจไม่ใส่ prefix ตัวอักษร
  เพราะเลขแบบ `ABC-1234` ไปชนรูปแบบรหัส ticket จริงของทีมอื่นในบริษัท

## กลไกสำคัญ: แชทเลื่อนขึ้นเองโดยไม่มี scrollbar

```
.viewport  overflow:hidden + mask ไล่จางที่ขอบบน 0→92px
.feed      position:absolute; bottom:0   ← กองจากล่างขึ้นบน
```

`.feed` ยึดก้นไว้ ข้อความใหม่ต่อท้ายเสมอ ส่วนที่โตพ้นกล่องจะทะลุขึ้นไปข้างบน
แล้วโดน `overflow:hidden` ตัด + mask ไล่จาง **ไม่มี scroll ไม่มีการย่อขนาด**

**ทำให้ลื่นยังไง** — ถ้าปล่อยตามธรรมชาติกองจะ "กระตุก" ขึ้นทีเดียว เลยใช้ทริก
ใน `push()`:

```js
feed.appendChild(el);
var h = el.offsetHeight;
el.style.marginTop = -h + "px";   /* หักความสูงตัวเองทิ้ง → กองไม่ขยับ */
el.style.opacity = "0";
el.offsetHeight;                  /* บังคับ reflow ก่อน ห้ามตัดทิ้ง */
el.style.transition = "margin-top .36s ..., opacity .3s ...";
el.style.marginTop = "0px";       /* คลายกลับ → ดันทั้งกองขึ้นพร้อมกัน */
```

> บรรทัด `el.offsetHeight;` ที่ดูเหมือนโค้ดขยะ **ห้ามลบ** — เป็นการบังคับ
> reflow ให้เบราว์เซอร์บันทึกค่าเริ่มต้นไว้ ถ้าไม่มี transition จะไม่เล่นเลย

`.msg` ใช้ `padding-top: 15px` แทน `margin-top` ในการเว้นระยะ **โดยตั้งใจ**
เพราะ `margin-top` ถูกจองไว้ให้อนิเมชันข้างบนใช้

## กลไกสำคัญ: append กับ rebuild

ต่างจากสไลด์ 1–2 ที่ใช้คลาส `bN` / `bN-in` — สไลด์นี้ DOM เปลี่ยนจริง
เลยแยกทางเดินเป็นสองแบบใน `setBeat()`

| กรณี | ทำอะไร |
| --- | --- |
| `n === beat + 1` (เดินหน้าปกติ) | `push()` — ต่อข้อความใหม่ทีละใบพร้อมอนิเมชัน |
| อย่างอื่น (ถอย / reset / กระโดด / reduced-motion) | `rebuild()` — ล้าง `.feed` แล้ววาดใหม่ 1..n ทันทีไม่มีอนิเมชัน |

ทำให้ถอยหลังกับ reset ได้ผลตรงกันเสมอโดยไม่ต้องเก็บ state อะไรเพิ่ม

## micro loop: "AI กำลังพิมพ์"

จุดสามจุดในฟองฝั่ง AI จะโผล่**ทุกครั้งที่จบ beat แล้วตาถัดไปเป็นของ AI**
(คือหลังข้อความฝั่งเราทุกใบ) เป็น element ชั่วคราวคลาส `.typing`
ไม่ได้อยู่ใน `MSGS` — `addTyping()` / `clearTyping()` จัดการเอง

`push()` เรียก `addTyping()` ที่ `at(400)` **หลังอนิเมชันจบ** ไม่งั้นกองจะกระตุกซ้ำ
ส่วน `rebuild()` เรียกทันทีเพราะไม่มีอนิเมชันอยู่แล้ว

## ⚠️ กับดักที่เคยเจอมาแล้ว

**1. ปุ่มควบคุมใช้เลข ไม่ใช่ pips** — สไลด์ 1–2 มี 2 กับ 4 beat เลยใช้จุดได้
16 จุดจะกลายเป็นแถบยาวรกจอ สไลด์นี้เลยเปลี่ยนเป็น `.count` แสดง `n/16` แทน
**ถ้าเพิ่ม/ลดข้อความ ไม่ต้องแก้อะไร** ตัวเลขคำนวณจาก `MSGS.length`

**2. ตอนตรวจงานผ่าน Browser pane ภาพจะค้าง** — pane ถูก throttle เฟรม
ทำให้ screenshot โชว์ข้อความซ้อนกันมั่วเหมือนบั๊ก ทั้งที่ค่าจริงถูกต้อง
**ให้เช็คด้วย JS แทน** ก่อนสรุปว่าพัง:

```js
Array.from(document.querySelectorAll('#feed .msg')).map((e,i) => {
  const s = getComputedStyle(e);
  return i + ': mt' + s.marginTop + ' op' + s.opacity;
});
```

**3. `--accent` ใช้จุดเดียว** = ป้าย "จุดเปลี่ยน — AI ขอ context เอง"
ใต้ข้อความที่ 10 ห้ามเอาแดงไปใช้ที่อื่นในสไลด์นี้อีก เพราะจุดนั้นคือ
ที่ที่อยากให้สายตาไปหยุดพอดี
