## beat

`BEATS = 6` — beat เยอะไม่พอจะทำ pips เลยใช้เลข `n/6` ตามสไลด์ 3

| beat | เกิดอะไร | คำบรรยายใต้กล่อง |
| --- | --- | --- |
| 1 | บทสนทนาเต็ม 17 แถวฝั่งซ้าย + หน้าต่างแชทเปล่าฝั่งขวา | บทสนทนาทั้งหมดจากระดับ 01 |
| 2 | **ซิป** — 8 แถวฝั่ง AI จางไล่กันแล้วยุบสูงเป็น 0 กองรูดปิดมารวมกลาง หัวกล่องเปลี่ยน 17 → 9 | 8 ข้อความคือ AI เดา — เดาเพราะมันไม่มีข้อมูลจะใช้ |
| 3 | **FLIP** — 7 แถวที่เป็นข้อมูลจริงบินเข้าไปประกอบเป็นฟองใบเดียว / 2 แถวที่ไม่มีปลายทางจางหาย / กล่องซ้ายจางทั้งใบ | ที่เหลือคือของที่คุณรู้อยู่แล้วตั้งแต่ข้อความแรก |
| 4 | หน้าต่างแชทเลื่อนมากลางเวที + AI ขึ้นจุดสามจุด (= ส่งแล้ว) กองแชทเลื่อนขึ้น | รวบเป็นข้อความเดียว ส่งทีเดียว |
| 5 | คำตอบมาในฟองถัดไป หัวกล่องขึ้น `2 ข้อความ` | ได้สาเหตุที่แท้จริงตั้งแต่คำตอบแรก |
| 6 | สรุป **17 → 2** (เลข 2 เป็น `--accent` จุดเดียวของสไลด์) + บรรทัดรอง | *log อันนั้นรอบแรกคุณยังไม่รู้ว่าต้องแนบ — แต่รอบนี้คุณรู้แล้ว* |

ตัวนับบนหัวกล่องขวาไล่ **0 → 1 (beat 3) → 2 (beat 5)** ขนานกับ 17 ของกล่องซ้าย
— เป็นตัวเล่าเรื่องตัวที่สองที่ไม่ต้องพูดออกมา

## กล่องซ้าย — บทสนทนาย่อ

`ROWS` คือ 17 ข้อความจาก `MSGS` ของสไลด์ 3 ย่อเหลือบรรทัดเดียว
แถวไหนเป็น **"ข้อมูลจริง"** จะมีฟิลด์ `to: [...]` บอกว่าจะบินไปลงชิ้นไหนในฟอง

| index (0-based) | ปลายทาง | |
| --- | --- | --- |
| 0 | `ctx` | บริบท + error code |
| 2 | `lead`, `r0` | เปิดบรรทัด "เช็คไปแล้วดังนี้ครับ" พร้อมบุลเล็ตแรก |
| 4 | `r1`, `shot` | **เปิดทั้งบุลเล็ตและรูปหน้าจอ** เพราะข้อความเดิมคือ "ล้างแล้ว ยังเหมือนเดิม (แนบรูปหน้าจอ)" |
| 6 | `r2` | |
| 8 | `r3`, `r4` | **เบาะแสค่าจัดส่ง/ยอดรวมขึ้นเป็นขีด** ชิ้นที่ทำให้คำเฉลยลงล็อก — แถวเดียวเปิดสองบุลเล็ต |
| 10 | `data` | บล็อก log |
| 12 | `ask` | ประโยคขอปิดท้าย |
| 14, 16 | *(ไม่มี)* | คำขอบคุณ + `🙂👌` — ไม่ใช่ข้อมูล เลยไม่มีที่ไป จางหายเฉยๆ |

> **สองแถวที่ไม่มีปลายทางคือส่วนหนึ่งของสาร ไม่ใช่ของหลุด** — มันแสดงว่า
> อะไรที่ไม่ใช่ข้อมูลก็หายไปพร้อมกับคำเดาของ AI ไม่ต้องอธิบาย

### เลขที่ห้ามลืมคำนวณใหม่

แถวสูง `19px + margin-top 1px` = **20px × 17 แถว = 339px** พอดีในช่องสูง 352
(กล่อง 396 − แถบหัว 30 − padding 14) **เปลี่ยนขนาดตัวอักษรหรือเพิ่มแถวต้องคำนวณใหม่**

`.rows` ใช้ `justify-content: center` — พอแถว AI ยุบหาย 9 แถวที่เหลือจะไหลมารวมกลางเอง
เป็นการซิปที่ได้มาฟรีโดยไม่ต้องเขียนอนิเมชันเพิ่ม

## FLIP — ทำไมต้องบินเป็น "ผี"

`flyOne()` **ไม่ได้ย้ายแถวจริง** แต่ `cloneNode` แล้วเอาไปวางใน `.fly`
(ชั้นลอย `position:absolute; inset:0; z-index:4`) เหตุผลสองข้อ:

1. แถวจริงอยู่ใน `.rows` ที่ `overflow:hidden` — ย้ายออกนอกกล่องไม่ได้
2. ต้นทางกับปลายทาง**ขนาดไม่เท่ากัน** ถ้า `scale` ตัวหนังสือจะยืด

เลย **translate อย่างเดียวแล้ว cross-fade** ให้ปลายทางโผล่แทน แถวต้นทางถูก
`visibility: hidden` (ไม่ใช่ `display:none`) เพื่อไม่ให้กองขยับระหว่างบิน

พิกัดคำนวณด้วย `box(el)` ที่**หารสเกลของเวทีออกก่อน** — `getBoundingClientRect()`
คืนค่า px ของจอจริง ซึ่งไม่ใช่ระบบพิกัดเดียวกับ `.fly`

> ### 🪤 ฟองปลายทางต้องถูกวางเต็มใบ "แต่เนื้อในล่องหน" ตั้งแต่ต้น beat 3
> `fly()` สร้างฟองทั้งใบก่อนแล้วค่อย `showPieces(false)` — **ห้ามเปลี่ยนไปเป็น
> "ค่อยๆ ต่อชิ้นเข้าไป"** เพราะฟองจะยังโตไม่เสร็จตอนชิ้นหลังๆ วัดตำแหน่ง
> แล้วมันจะบินไปลงผิดที่

## ฉากล่าง y 556..720

**วนไม่รู้จบ ไม่ผูกกับ beat** ใช้ตัวจับเวลาคนละชุด (`sceneT` / `sat()`) กับของ beat
(`timers` / `at()`) เพราะ `clearTimers()` ตอนเดินหน้า-ถอยหลังจะฆ่าลูปทิ้ง

องค์ประกอบเหมือนสไลด์ 3 ทุกอย่าง (ตู้ rack, ตัวละคร 30%, `z-index` ตู้สูงกว่าตัวละคร
หุ่นเลยเลื่อนหายเข้าไปหลังตู้จริงๆ, `is-busy` = LED กะพริบถี่ + แถบสแกน)
แต่**ต่างสองข้อ**:

### 1. รอบเดียวจบ (สไลด์ 3 วิ่ง 3 รอบ)

ลูปยาว ~22.5 วินาที:

| เวลา | |
| --- | --- |

| 1.4s | หุ่นออกจากตู้ ไฟกลับไปนิ่ง เดินมาหา (2.1s) |
| 3.7s | **คนเริ่มพิมพ์** — 7 บรรทัด ห่างกัน 340ms หุ่นยืนรอทั้งช่วง |
| 7.0s | ส่ง → หุ่นขึ้น `✓` รับทราบ |
| 8.0s | หุ่นกลับเข้าตู้ ทำงาน 2.4s (`is-busy`) |

### 2. บอลลูนของคน "ค่อยๆ พิมพ์"

บอลลูนฝั่งคนไม่ได้โผล่ทั้งก้อนแบบสไลด์ 3 แต่เป็น **skeleton ย่อส่วนของฟองพรอมต์
ข้างบน** ที่ต่อทีละบรรทัด ตามตาราง `SK`:

| ลำดับ | ชนิด | กว้าง |
| --- | --- | --- |
| 1–2 | `bar` ย่อหน้า | 48, 66 |
| 3–5 | `bl` บุลเล็ต (จุด 4px + gap 5px + แท่ง) | 66, 73, 81 |
| 6 | `im` กล่องรูป (มีขอบ + จุดมุมบนซ้าย) | 30 |
| 7 | `bar` ย่อหน้าปิดท้าย | 104 |

แต่ละแท่งกางจาก `width: 0` ไปหาเป้าใน 260ms และกล่องบอลลูนขยายตาม
(48 → 124px กว้าง / 20 → 72px สูง)

**ฝั่งหุ่นยังโผล่ทั้งก้อนเหมือนเดิม** — ตั้งใจให้ตัดกันว่าฝั่งคนใช้เวลาเรียบเรียง
ฝั่งหุ่นตอบพรวดเดียว

## กับดัก

### 1. ขนาดบอลลูนคำนวณจากตาราง ไม่ได้วัดจาก DOM

`--sw` / `--sh` มาจากการบวกเลขใน `SK` ตรงๆ เพราะสองเหตุผล:
`width: auto` **ทรานซิชันไม่ได้** และตอนที่จะวัด แท่งยังกางไม่เสร็จ (อยู่ระหว่าง transition)
`.say.is-sk` เลยต้องมี `box-sizing: border-box` เพราะสูตรรวม padding + border มาแล้ว
— **ตอนแรกลืมใส่ บอลลูนเลยสูงเกินไป 16px จนล้ำเข้าไปในโซนคำบรรยาย**

### 2. ฉากสไลด์นี้เตี้ยกว่าสไลด์ 3 อยู่ 16px

สูง **164px** (สไลด์ 3 สูง 180) ค่าแนวตั้งเลยถูกดันขึ้นจาก 30 → **18** ทั้งชุด
(`.floor` / `.rack` / `.pawn`) ส่วน**ค่าแนวนอนใช้ของสไลด์ 3 เป๊ะ**:

```js
var BOT_HOME = 362;   // กลางตู้ rack
var BOT_TALK = 816;   // จุดที่หุ่นมายืนคุยกับคน
var GUY_X    = 891;   // ทั้งฉากกิน x 342..938 กึ่งกลาง 640 = กลางเวที
```

ตอนบอลลูนกางเต็ม ขอบบนอยู่ที่ **y 561** เหลือที่ว่างจากขอบฉาก (556) แค่ 5px
→ **เพิ่มบรรทัดใน `SK` อีกต้องคำนวณใหม่**

### 3. `rebuild()` ต้องปิดอนิเมชันชั่วคราว

ถอยหลัง / รีเซ็ต / `prefers-reduced-motion` ใช้ `rebuild(n)` วางสถานะตรงๆ
มันใส่คลาส `is-jump` บน `.stage` ซึ่ง `transition: none !important` ทุกลูก
แล้วบังคับ reflow (`stage.offsetHeight`) ก่อนถอดคลาสออก — **ห้ามลบบรรทัดนั้น**
ไม่งั้นกล่องจะเลื่อนให้เห็นตอนกดถอย

### 4. เดินหน้าทีละ 1 beat เท่านั้นที่ได้อนิเมชัน

`setBeat()` เช็ค `n === beat + 1` — กระโดดข้าม beat หรือถอยหลังจะ `rebuild()` เสมอ
`STEP` มีแค่ beat 2–5 (beat 1 กับ 6 ไม่มีอะไรต้องอนิเมท คำบรรยายเปลี่ยนใน `paint()`)

### 5. บีต 4–5 ยอดฟองพรอมต์เลื่อนพ้นจอ

เป็นความตั้งใจ (เหมือนแชทจริง) คนดูอ่านพรอมต์เต็มๆ ที่บีต 3 แล้ว
**ผู้พูดต้องหยุดให้อ่านที่บีต 3 จริงๆ** ไม่ใช่รัวผ่าน

### 6. Browser pane ส่งเฟรมค้าง

เหมือนสไลด์ 3 — สกรีนช็อตจาก preview pane มักเป็นเฟรมเก่า (rAF ถูก throttle
ตอน pane ซ่อน) ทำให้ดูเหมือนอนิเมชันพัง **ให้เช็คด้วย `javascript_tool`
อ่านค่า class / `getBoundingClientRect` แทน** แล้วค่อยถ่ายซ้ำอีกทีเพื่อบังคับเฟรมใหม่
