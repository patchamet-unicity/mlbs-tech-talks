# สไลด์ 5 — `05-context.html`

**ระดับ 03 Context** — เอาพรอมต์ยาวใบเดิมจากสไลด์ 4 มา**ผ่าเป็นสองกอง**
กองที่เหมือนกันทุกเคสถูกยกออกไปเขียนเป็น **ไฟล์ context ใบเดียว**
ตั๋วใบใหม่เลยถามสั้นๆ ได้ เพราะไฟล์ถูกแนบไปด้วยทุกครั้ง
อ่าน [README.md](README.md) ก่อนถ้ายังไม่เคยอ่าน (เวที 1280×720, ระบบ beat, ปุ่มควบคุม ฯลฯ)

> **ใจความที่ต้องไม่หลุด:** ระดับ 02 คือ *"พิมพ์ให้ครบ"* ระดับ 03 คือ
> *"ไม่ต้องพิมพ์อีกแล้ว เพราะมันอยู่ในไฟล์"* — **ข้อความสั้นลง แต่ผลดีขึ้น**
> ซึ่งหักมุขที่สไลด์ 4 เพิ่งสร้างไว้ (ยิ่งเขียนยาวยิ่งดี) โดยตั้งใจ

## ⚠️ ไฟล์เดียวเท่านั้น

เวอร์ชันแรกทำเป็น **ชั้นวางที่มีการ์ดหลายใบ + ซ็อกเก็ตต่อ DB/log +
แผงชื่อเครื่องมือ (Claude Code / Codex / Cursor)** — user ตีกลับทั้งชุด (2026-08-30)

ระดับ 03 ต้องเป็นแค่ **"คุณเขียนไฟล์ไว้ใบเดียว แล้วมันถูกแนบไปทุกครั้ง"**
เรื่อง DB / log / API ยังอยู่ — แต่อยู่**ในไฟล์ ในฐานะ "ที่อยู่ของของ"** ไม่ใช่ท่อที่ต่อจริง

**อย่าเอาชั้นวางหลายชิ้น / ซ็อกเก็ต / ชื่อเครื่องมือ กลับมา**

## ⚠️ หมัดเด็ดอยู่ที่ beat 3 — ห้ามแก้ประโยคนี้

ข้อความที่พิมพ์ในบีต 3 คือ

> **คนไม่ได้เก่งขึ้น AI ก็ตัวเดิม สิ่งที่เปลี่ยนคือของรอบตัวมัน**
> — ซึ่งเป็นแกนของ talk ทั้งเรื่อง

**ถ้าไปแก้ประโยคนี้ให้ต่างจากสไลด์ 3 มุกทั้งสไลด์ตาย** ถ้าจะแก้ ต้องแก้สองไฟล์พร้อมกัน

## beat

`BEATS = 6` — ใช้เลข `n/6` แทน pips ตามสไลด์ 3–4

| beat | เกิดอะไร | คำบรรยายใต้กล่อง |
| --- | --- | --- |
| 1 | พรอมต์ยาวใบเดิมจากระดับ 02 ผ่าสองกอง มีป้าย `เฉพาะเคสนี้` / `เหมือนกันทุกเคส` | พรอมต์ยาวๆ ของระดับ 02 มีของสองอย่างปนกันอยู่ |
| 2 | กอง `keep` ยุบหายจากฟอง แล้วกลายเป็นไฟล์ฝั่งซ้าย โผล่ทีละบล็อก | ของที่เหมือนเดิมทุกครั้ง ย้ายไปเขียนไว้ในไฟล์เดียว เขียนครั้งเดียวพอ |
| 3 | ตั๋วใหม่ พิมพ์ประโยคเดียว (**callback สไลด์ 3**) ชิปชื่อไฟล์โผล่ใต้ข้อความ | ตั๋วใบใหม่ พิมพ์แค่ประโยคเดียว + บรรทัดรองชี้มุก callback |

ตัวนับหัวกล่องขวาไล่ `1 → 1 → 1 → 2 → 4 → 4 ข้อความ`

### ทำไมตั๋วใบที่ 2 ต้องเป็นอาการที่ "ไม่มี error"

`Q2` จงใจเขียนว่า *กด checkout แล้วค้าง ไม่ขึ้น error อะไรเลย* เพราะถ้าอาการมีรหัส error
มันจะไปใช้บรรทัดชุดเดิมกับใบแรก แล้วมุก "ไฟล์เดียวกันแต่คนละบรรทัด" จะไม่เกิด
คำตอบใบนี้เลยต้องเริ่มจาก **log** (ขั้นตอนที่ 1) และ **API** ซึ่งใบแรกไม่ได้แตะ

ส่วนใบแรกเข้าทางขั้นตอนที่ 3 พอดี (*ถ้ารายอื่นปกติ ให้สงสัยข้อมูลของรายนั้นก่อน*)
เพราะ "ข้อมูลของรายนั้น" คือรหัสไปรษณีย์ที่ตารางโซนไม่รู้จัก

### บรรทัดกันโกงในบีต 6

> ไฟล์ไม่ได้เขียนตัวเอง ต้องมีคนเขียนและคอยอัปเดตเมื่อระบบเปลี่ยน —
> และมันบอกได้แค่ว่าของอยู่ที่ไหน ใครจะไปหยิบมาให้ ยังเป็นอีกเรื่อง

ประโยคหลังคือสะพานไปสไลด์ agent harness ต่อ **อย่าตัดทิ้ง** สไลด์ 4 ก็มีบรรทัดแบบนี้
ด้วยเหตุผลเดียวกัน (คนดูเป็น dev ถ้าขายเกินจริงจะโดนจับได้)

## ⚠️ กับดัก

1. **ต้อง "ปิดงาน" บีตก่อนหน้าให้เรียบร้อยก่อนเล่นบีตถัดไป**
   `setBeat()` เรียก `rebuild(n - 1)` ก่อนรัน `STEP[n]` เสมอ
   เพราะ STEP หลายตัวทยอยเปิดของด้วย `at()` ถ้าคนกดรัวๆ `clearTimers()` จะฆ่า timer
   ที่ยังไม่ทำงาน แล้ว**ไฟล์หรือของบนจอจะหายไปทั้งอัน** (เจอจริงตอนกดถี่ 200ms)
   `rebuild()` วางสถานะแบบไม่มีอนิเมชัน เลยปลอดภัยที่จะเรียกซ้ำ
2. **เนื้อไฟล์ล้นกรอบง่ายมาก** ช่อง `.doc` สูง 358 เนื้อปัจจุบันเต็มพอดี เหลือ 0px
   ตอนเพิ่มบรรทัด `ทีมที่เกี่ยวข้อง` กับฟอร์แมตคำตอบที่ยาวขึ้น ล้นไป 40px
   ต้องไล่บีบทีละอย่าง: `font-size` 12.5→12 · `line-height` 1.45→1.38 ·
   `.ds` margin 8→6 · padding ล่าง 11→4 · ตัดฟอร์แมตคำตอบให้เหลือ 2 บรรทัด
   **จะเติมอะไรอีก ต้องเอาอย่างอื่นออกก่อน** เช็คด้วย `doc.scrollHeight - doc.clientHeight`
3. **กอง `keep` เป็นสีครีม ฟองฝั่งเราก็สีครีม** ครีมทับครีมมองไม่ออก
   ฟองพรอมต์ของบีต 1 เลยต้องมี class `split` ที่ดันพื้นเป็น `--ground-light`
   (`.msg.split .bub`) และกินเต็มความกว้าง — `.msg.you .col` มี `align-items: flex-end`
   อยู่ ต้องสั่ง `width: 100%` ที่ตัว `.bub` เองด้วย ไม่งั้นฟองหดตามเนื้อ
4. **บีต 6 ต้องซ่อนหน้าต่างแชท ไม่ใช่หรี่** เคยทำ `opacity: .32` แล้วตัวหนังสือ
   ของแชทกับของตั๋วทับกันจนอ่านไม่ออกทั้งสองชั้น — ตอนนี้ใช้ `opacity: 0`
5. **`hilite()` ต้องล้างของเดิมก่อนเสมอ** ไม่งั้นชุด `a` กับ `b` จะติดค้างทับกัน
   แล้วมุก "คนละบรรทัด" พัง
6. **`--accent` ใช้จุดเดียว: กอง `keep` ในบีต 1** (เส้นซ้าย + ป้าย) เพราะกองนั้นคือ
   ของที่ทั้งสไลด์กำลังจะพูดถึง — ไฮไลต์ในไฟล์ใช้ครีม `--frame`
7. **บรรทัดคำบรรยายบีต 6 ยาวสองบรรทัด** วัดแล้วขอบล่างอยู่ที่ y 552 ชนขอบฉาก 556 พอดี
8. **Browser pane ชอบส่งเฟรมค้าง** ตอนตรวจงานอย่าเชื่อ screenshot อย่างเดียว
   ให้อ่าน `classList` ผ่าน `javascript_tool` ประกอบด้วย (เจอเหมือนสไลด์ 4)

**ลูปสั้นกว่าสไลด์ 4 เกือบครึ่ง (~19.5 วิ เทียบ ~22.5)** — ความสั้นนี่แหละคือใจความ
สไลด์ 4 คน "ค่อยๆ พิมพ์" ทีละบรรทัดจนบอลลูนขยาย ส่วนสไลด์นี้**คนพูดคำเดียวจบ**
(`CALL_LINES` ฟองเดียว) เพราะของที่เหลืออยู่ในไฟล์แล้ว
ถ้าไปทำให้ลูปนี้ยาวเท่าสไลด์ 4 ความหมายจะหายไป

ตัวละครใช้ `--char-size: 60px` (30% ของสไลด์ 1) เหมือนสไลด์ 3–4
**หุ่นไม่มีเฟรมเดิน** เลย "ลอย" ไปมาด้วย transition ของ `--x`
