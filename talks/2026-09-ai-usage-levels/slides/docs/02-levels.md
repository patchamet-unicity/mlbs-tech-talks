## beat

**4 beat = 4 ระดับ** (`BEATS = LEVELS.length`)

| beat | ระดับ | ของที่โชว์บนแถบกลางจอ | micro loop |
| --- | --- | --- | --- |
| 1 | Chat | กล่องแชท 2 ใบ **เกยกัน** เป็นเธรด | `▪ ▪ ▪` วิ่งในกล่องขวา (typing indicator) |
| 2 | Prompt Engineer | เกยกันเหมือนกัน กล่องซ้ายใหญ่ขึ้น มีหัวข้อ / ย่อหน้า / bullets | เคอร์เซอร์ `▌` กะพริบท้าย bullet สุดท้าย |
| 3 | Context Engineer | เอกสาร 1 ชิ้น ชั้นกระดาษ **2 ใบ** | ใบบนขยับขึ้น-ลง 3px รอบ 2.8s |
| 4 | Agent Harness | เอกสาร 1 ชิ้น ชั้นกระดาษ **5 ใบ** + เครื่องมือ 6 ชิ้นกองข้างๆ | แว่นขยายส่ายซ้าย-ขวา + เคอร์เซอร์ terminal กะพริบ |

แต่ละ beat: เสาขั้นใหม่โผล่ขึ้นมา + **คนกระโดดขึ้นไปยืนขั้นนั้น** เสาเก่าค้างไว้เต็มสี
เสาที่กำลังยืนอยู่เน้นด้วย **ขอบบนหนาขึ้น + เลขระดับเป็นสีแดง `--accent`**

จบ beat แล้ว `▼` มุมล่างกะพริบ = รอคลิก

## กฎการออกแบบที่ตั้งใจไว้ (อย่าเผลอแก้)

1. **ของแต่ละ beat "แทนที่" ไม่ใช่ "สะสม"** — เสาที่ค้างอยู่ทำหน้าที่บันทึกว่าผ่านอะไรมาแล้ว
   ถ้าให้ของกอง 4 ชุดพร้อมกันจะรกจนอ่านไม่ออก
2. **ข้อความในกล่อง/เอกสารเป็นแท่งขีด อ่านไม่ออกโดยตั้งใจ** — ประเด็นอยู่ที่*ปริมาณ*
   และ*โครงสร้าง* ไม่ใช่เนื้อหา และกันคนดูมัวอ่านแทนที่จะฟังคนพูด
3. **beat 3 ต้องดูน้อยกว่า beat 4 ชัดเจน** — ต่างกันแค่ความหนาของกองกระดาษ (2 ใบ vs 5 ใบ)
   เทียบกันปุ๊บเห็นเลย ถ้าไปเพิ่มเอกสารให้ beat 3 จะเสีย contrast ตรงนี้
4. **beat ละ micro loop เดียว (beat 4 สอง)** — สไลด์นี้ค้างบนจอตอนคนพูด
   ถ้ามีของขยับหลายจุดคนดูจะละสายตาจากคนพูด
5. **4 เสาเมื่อแสดงครบต้องอยู่กึ่งกลางจอ** — `STEP_X0 + BEATS * STEP_W` ต้อง symmetric รอบ 640
   ตอนยังไม่ครบ เสาจะเยื้องไปทางซ้าย (ตำแหน่งตายตัว ไม่ re-center ทุก beat โดยตั้งใจ
   เพราะถ้าเสาขยับทุก beat จะอ่านจังหวะกระโดดยาก)

## ⚠️ กับดักที่ต้องระวังที่สุด

### `GROUND` ใน JS ต้องเท่ากับ `bottom` ของ `.floor` และ `.step`

```
.floor { bottom: 28px }      ─┐
.step  { bottom: 28px }       ├─ ต้องเท่ากันทั้งสามที่
var GROUND = 28;             ─┘
```

`GROUND` ไม่ได้ใช้แค่วางเส้นพื้น แต่ถูกใช้**คำนวณความสูงเสา**ด้วย:

```js
el.style.height = (SURFACE0 + i * RISE - GROUND) + "px";
```

ถ้าขยับเส้นพื้นใน CSS แต่ลืมแก้ `GROUND` → เสาจะสูงผิด แล้ว**คนจะยืนลอยเหนือเสา
หรือจมลงไปในเสา** (บั๊กนี้เคยเกิดจริงตอนขยับเส้นพื้นจาก 60 → 40)

### แถบแสดงของกับหัวสไลด์/หัวคน ชนกันง่าย

```
หัวสไลด์จบที่     y 130
แถบแสดงของ        y 150 .. 326   ← ของ align ชิดล่าง โตขึ้นบน
หัวคนตอนยืนขั้น 4  y 332
```

`.props` ใช้ `align-items: flex-end` ของจึงงอกขึ้นข้างบน **ถ้าเพิ่มบรรทัด/ความสูง
ให้ของ beat ไหน มันจะดันขึ้นไปชนหัวสไลด์** (เคยเกิดกับ beat 2 มาแล้ว)
`padding-bottom: 20px` ของ `.props` มีไว้ให้หางบอลลูนห้อยลงมาโดยไม่ดันความสูง

วิธีเช็ค: เปิดหน้าแล้วรันใน console

```js
var st = document.querySelector('.stage').getBoundingClientRect();
var s  = parseFloat(getComputedStyle(document.getElementById('stage')).getPropertyValue('--stage-scale'));
var f  = el => ({ t: Math.round((el.getBoundingClientRect().top - st.top) / s),
                  b: Math.round((el.getBoundingClientRect().bottom - st.top) / s) });
console.log(f(document.querySelector('.head')), f(document.querySelector('#props > *')));
```

### เอกสารกองซ้อนไปทาง "ซ้าย-ล่าง" ก้นเสมอกัน

`.stack .ghost` ถูกวางด้วย inline style `left: -k*11px; top: k*8px; bottom: 0`
ทำให้ใบหลังเตี้ยลงและเยื้องซ้าย = ภาพกองกระดาษที่ก้นเสมอกัน
**ความกว้างที่กินจริงจึงมากกว่า `w` ของ `.stack` อยู่ `(sheets-1) * 11px` ทางซ้าย**

## ไอคอนเครื่องมือ (beat 4)

ปั้นเป็น **SVG พิกเซลกริด 13×13** ทั้งหมด **ไม่ใช้ Unicode / emoji**
— เพราะ emoji บังคับสีไม่ได้ (จะกลายเป็นจุดสดที่สุดในจอ แตกพาเลตต์)
และกลิฟ Unicode หน้าตาเปลี่ยนตามฟอนต์ของเครื่องที่ฉาย

เก็บไว้ในตัวแปร `ICONS` เป็น array ของ `[x, y, w, h]`:

```js
var ICONS = {
  gear: { ink: [...], hole: [[5,5,3,3]] },   // hole = เจาะทะลุเห็นพื้นหลัง
  mag:  { ... },  plug: { ... },  db: { ... },  link: { ... }
};
```

- แก้ทรงไอคอน = แก้ array ที่นี่ที่เดียว
- สีมาจาก `currentColor` → `.icon { color: var(--ink) }`
- `term()` (กล่อง `>_`) **ไม่ใช่ SVG** เป็น `div` ขอบหนา เพราะเข้าชุดกับกล่องอื่นในสไลด์มากกว่า
- **บทเรียน:** ไอคอน `link` รอบแรกวาดเส้นหนา 1px แล้วอ่านไม่ออกตอนย่อ
  เส้นบนกริด 13×13 ควรหนาอย่างน้อย **2px**

**เฟืองหมุนได้แต่ปิดไว้** — keyframe `gearSpin` ใช้ `steps(8)` (กระโดดทีละฟัน)
คอมเมนต์ทิ้งไว้ใต้ `.icon-mag` เปิดได้บรรทัดเดียว
> ถ้าจะให้เฟืองหมุน **ห้ามหมุนเนียน** ต้องเป็น `steps()` ไม่งั้นหลุดจากภาษาพิกเซลของงานทันที

## ค่าที่แก้บ่อย

```js
var NEXT = "03-examples.html";   // ยังไม่มีไฟล์นี้ — กด ▶ ที่ beat 4 จะ 404
var PREV = "01-title.html";

var STEP_W   = 210;   // ความกว้างเสา
var STEP_X0  = 220;   // ขอบซ้ายเสาแรก — 220 + 4*210 = 1060 → กึ่งกลางจอพอดี
var SURFACE0 = 124;   // ความสูงผิวเสาแรก นับจากก้นเวที
var RISE     = 48;    // สูงขึ้นขั้นละเท่าไหร่
var GROUND   = 28;    // ต้องตรงกับ CSS (ดูหัวข้อกับดักด้านบน)
var HUMAN_W  = 120 * 40 / 51;   // ความกว้างสไปรต์ = char-size * อัตราส่วน 40:51

var AUTO_HOLD = [0, 2600, 2600, 2600, 6000];
```

| อยากแก้ | ไปที่ |
| --- | --- |
| ชื่อ/เลขระดับ | `LEVELS` |
| ของที่โชว์แต่ละ beat | `PROPS` — ประกอบจาก helper `thread()` `chat()` `stack()` `lines()` `bullets()` `icon()` `term()` |
| จำนวนชั้นกระดาษ | argument ที่ 4 ของ `stack(w, h, inner, sheets, breathe)` |
| ความกว้าง/ความชันบันได | `STEP_W` / `RISE` (แล้วเช็คว่ายังกึ่งกลางจอ) |
| ขนาดคน | `.actor { --char-size: 120px }` — **ต้องแก้ `HUMAN_W` ตามด้วย** |
| ตำแหน่งแถบแสดงของ | `.props { top: 150px; height: 176px }` |
| ระดับพื้น | `.floor` + `.step` + `GROUND` (ทั้งสามที่) |
